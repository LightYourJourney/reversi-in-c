# 路线图

按阶段增量交付。每个阶段结束时必须提供可复现的构建/测试结果；
无法验证的内容明确标注“未验证”。

## Phase 0 — 工程初始化与技术架构（已完成，2026-10-19）

交付内容：

- 模块化目录与依赖方向
- CMake 构建（C11、Debug/Release、CTest、可选 ASan/UBSan）
- raylib 6.2 固定版本与系统包优先策略
- 最小可运行窗口程序与干净退出
- 不依赖 GUI 的 core.board 测试目标
- README、架构文档、路线图、Phase 0 报告

验收结果：Debug、Release、ASan+UBSan 三套构建通过；CTest 1/1 通过；
窗口程序在三种构建下均以退出码 0 正常关闭。

## Phase 1 — 规则引擎

目标：完整、可测试的标准 8×8 翻转棋规则。

- `core/rules`：八方向合法着法生成、夹住判定、翻转列表
- 无合法着法时的跳过逻辑接口
- 终局判定与黑白计分
- 初始局面黑方四个合法着法（d3、c4、f5、e6）
- 已知局面回归测试与随机对局不变量测试
- 规则层保持零 GUI 依赖

验收标准：

- 规则测试覆盖合法/非法落子、八个方向、边界、跳过与终局
- 随机对局中棋子总数 + 空格数恒为 64，且无非法翻转
- 不修改 UI 或引入 raylib

## Phase 2 — 对局控制与历史

目标：可完整进行一局本地双人对战。

- `Game`：当前玩家、落子、跳过、终局、计分
- `History`：着法栈、撤销、重做、重新开始
- 状态一致性：撤销后重做必须回到完全相同的局面
- 测试：完整对局、连续跳过、撤销/重做边界

验收标准：

- 一局可从开局走到终局，无需 UI
- 撤销/重做/重开测试通过
- 非法落子不能改变任何状态

## Phase 3 — 图形界面与交互

目标：具有设计感且可靠的棋盘与对局界面。

- 棋盘、棋子、落子提示、最后一步标记
- 悬停反馈、落子动画、翻转动画
- 计分板、当前回合、跳过/终局提示
- 鼠标/键盘输入、窗口缩放适配
- 新开一局与退出入口

验收标准：

- 所有交互通过真实窗口手动验证
- `--frames` 冒烟测试持续通过
- 规则层没有被 UI 状态污染

## Phase 4 — AI 与难度

目标：多种难度的人机对战，AI 永不非法落子。

- 随机、贪心、Alpha-Beta 极小化极大搜索
- 迭代加深与时间预算
- 评估函数：角点、边、机动性、稳定子、奇偶
- 难度分级
- AI 合法性测试：大量局面下返回的落子必须属于合法着法集合
- AI 只读取快照，不修改 UI 或全局状态

验收标准：

- 所有难度在测试局面中零非法落子
- AI 思考不阻塞窗口事件循环（必要时使用工作线程）
- 相同局面的搜索结果可复现（固定种子/确定性）

## Phase 5 — 菜单、设置与存档

目标：完整的产品化外壳。

- 主菜单、模式选择、难度选择、设置页
- 用户配置持久化（音量、动画、先手、主题等）
- 存档/读档，格式带版本号与校验
- 损坏/不兼容存档被安全拒绝
- 存档往返测试

验收标准：

- 从菜单可进入本地双人或人机对战
- 关闭并重启后设置与存档可恢复
- 非法存档不会导致崩溃或未定义行为

## Phase 6 — 打磨与发布

目标：达到可长期维护和分发的质量。

- 音效与视觉反馈
- 动画细节、可访问性（色盲对比、键盘操作）
- 性能与内存检查（ASan/UBSan、必要时 LeakSanitizer）
- macOS 实机验证；Windows/Linux 构建验证
- CI：格式/警告/测试/构建矩阵
- README 与文档最终校对

验收标准：

- 干净环境按 README 步骤可构建、运行、测试
- 所有自动化测试通过
- 无已知严重缺陷
- 跨平台状态如实记录（未验证的平台明确标注）

## 非目标（当前）

- 在线对战、账号系统、网络协议
- 移动端与 Web 构建
- 第三方 UI 框架或资源商店素材

这些方向如需加入，应先更新架构文档并评估对模块边界的影响。

# Reversi Lab 分析架构（Phase 12）

日期：2026-10-24  
版本：1.3.0

## 1. 目标与边界

Reversi Lab 是独立于正式对局的复盘与分析模式。它复用同一套
`core/rules`、`core/game` 与 AI 搜索，不引入第二套规则实现。

边界：

- `AnalysisSession` 只读写自己的局面树，从不修改 `Match`。
- UI 通过分析 API 读取结果；后台线程不接触 UI、`Match` 或会话。
- 正式对局仍只通过 `match_apply_move()` 落子；分析模式不是正式对局的
  旁路。
- 分析页面可以自由摆盘，但自定义局面明确标记为 `CUSTOM`，不会被当作
  合法棋谱历史。

## 2. 分层

```text
app ── ui/lab_view (编译进 app)
 │        │
 │        ├── analysis  (局面树、棋谱格式)
 │        └── ai/ai_analyze + ai_worker
 └── core/rules、core/game
```

`reversi_ui` 不依赖 AI；Lab 视图放在 `src/ui/lab_view.c`，但编入
`reversi_app`，使 `ui.*` 单元测试仍只链接 UI 与 core。

## 3. 数据模型

| 类型 | 职责 |
|---|---|
| `AnalysisSession` | 固定容量的局面池、根节点、当前节点；所有导航与编辑的入口 |
| `AnalysisPosition` | 一个完整 `GameState`、父/子/兄弟索引、到达它的 `AnalysisMove`、`VALID` 或 `CUSTOM` |
| `AnalysisMove` | 一次着法或显式 Pass，含行动方与“对手是否被自动跳过” |
| `AnalysisVariation` | 从某节点沿首子链到叶的可比较分支视图 |
| `AnalysisResult` | 当前局面的终局结果、双方子数与是否终局 |

关键语义：

- 子节点按创建顺序链接；**首子链是主线**。
- 从当前节点重放一个已存在的着法会导航到该子节点，不创建重复节点。
- 在历史节点下走另一着法会创建兄弟分支；`analysis_next_variation()` /
  `analysis_return_to_main()` 在分支与主线间切换。
- Pass 是一个独立节点（`via.is_pass`），不是“空着法”。
- `VALID` 表示可追溯到标准开局；`CUSTOM` 表示由编辑器构造。从
  `CUSTOM` 局面继续走子仍保持 `CUSTOM`。
- 任何编辑都会把当前局面变成新的 `CUSTOM` 根并丢弃旧树：手工编辑后
  再保留旧分支会暗示一段从未发生的历史。
- 池上限 512 个局面、64 个 ply；超出时操作返回 false，不破坏已有树。
- `VALID` 根只接受标准开局；其他合法局面通过 `History` 导入或着法重放
  得到，保证“可由合法着法产生”是可检查的。

## 4. AI 分析接口

`ai_analyze_position(state, config, max_lines, out)` 是只读接口，位于
`ai/ai_search.c`，与 `ai_choose_move()` 分开：

- 不调用、不修改正式对局的选着路径；输入 `GameState` 不被修改。
- `max_lines` 限制在 1–3。
- 对每个候选使用**同一深度、全窗口**搜索：逐层迭代，每层搜索所有根着法；
  若某层被取消或超时，整层丢弃并保留上一层结果。因此同一结果内所有候选的
  分数可直接比较。
- `complete` 只在到达 `max_depth` 时为真；`exact` 只在剩余空位 ≤12 且
  已完成完整空位深度时为真（终局分数精确）。
- 分析模式关闭 TT 的分数截断，只把 TT 用于着法排序，避免把边界分数当成
  精确根分数。
- PV 从 TT 重建，每个着法在报告前都经过规则重放验证；遇到 Pass、TT 未命中
  或长度上限即停止，因此 PV 可能短于报告深度。
- 统计字段（节点、剪枝、TT 命中、耗时）来自本次分析，不与正式对局的
  `AiStats` 共用。

评估分量直接复用 `ai_evaluate()`。UI 用
`ai_evaluation_to_black()` 把“行动方视角”转换为固定“黑方为正”，并在
界面标明。启发式分数不是胜率；未校准前不显示百分比。

## 5. 任务生命周期

```text
position_generation ──► requested_generation
        │                      │
        └── 导航/编辑/导入 ─────┘（旧结果被丢弃）
```

- 每次局面变化递增 `position_generation`，并取消正在运行的分析。
- 启动任务时记录 `requested_generation`；结果返回后只有二者相等才被接受。
- 桌面端使用 `ai_worker` 的后台线程；Web 端使用同一份 C 搜索的 Web Worker。
- 取消：桌面置取消标志并 join；Web 直接终止 Worker。
- 线程只写自己的结果结构；UI 在主线程调用 `ai_worker_take_analysis()` 取走。
- 批次分析（Analyze all）逐局面复用同一个 Worker；当前局面保持不变，
  每个结果按主线的 ply 写入评分数组。

## 6. UI 结构

宽屏（≥760×600，即桌面最小窗口）：

```text
┌──────────────────────────────────────────────┐
│ Back  Load game  Copy record  Paste record   │
├───────────────────────────┬──────────────────┤
│                           │ Analyze/Stop/All │
│         棋盘              │ Main / Edit      │
│   候选落点高亮            │ MultiPV + PV     │
│                           │ 评估分量         │
├───────────────────────────┴──────────────────┤
│ 时间轴控制 | 评分曲线 | 当前 ply              │
└──────────────────────────────────────────────┘
```

窄屏（Web 手机/平板）：棋盘在上，分析面板在下，底部保留播放控制；
评分曲线与部分次要文字在窄屏隐藏，避免遮挡棋盘。

快捷操作：`M` 标记当前 ply；↑ 切换到上一个兄弟分支，↓ 切换到下一个；
点击评分曲线跳转到对应回合；Esc 返回菜单。当前节点与主兄弟都分析过时，
复盘区并排显示两者分数，深度不同会明确标注。

棋谱保存到用户数据目录的固定文件 `lab-record.rvr`（原子写入），
“Load record” 读回；没有文件选择器。自定义局面拒绝导出：它没有标准
开局历史，写成 `moves` 会伪造一段不存在的棋谱。

## 7. 已知限制

- PV 依赖 TT，深度较深的非最佳候选可能只得到较短 PV。
- 评分曲线来自已分析局面的最佳着法分数；它是“最佳着法评估变化”，
  不是对玩家着法的独立判决，也不构成胜率。
- `Analyze all` 的每步预算固定为 1.5 s、深度 8；未实现可变预算或
  “仅分析失误”的筛选。
- 棋谱使用固定文件名 `lab-record.rvr`，没有文件选择器或多份棋谱管理。
- 自定义局面不能导出为棋谱；导入的棋谱总是从标准开局开始。
- 自定义局面不校验“能否从标准开局到达”，只校验棋盘与规则一致性。

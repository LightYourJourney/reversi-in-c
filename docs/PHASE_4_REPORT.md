## 1. 交付范围

本阶段实现完整、可验证、三档难度的人机对战：

- Negamax + Alpha-Beta 搜索，显式 pass 节点，双方无着法时精确终局计分
- 迭代加深、时间预算、取消回调、置换表（Hard）、着法排序、残局深度扩展
- 分阶段评估：角点、机动性、潜在机动性、位置权重、边稳定子、前沿子、
  棋子数、奇偶；每个分量单独保存在 `AiEvaluation`
- Easy / Medium / Hard 三档真实不同参数与算法
- 后台搜索线程（POSIX `pthread` / Windows `CreateThread`），状态快照与
  原子取消/完成标志
- `AI_THINKING` 对局阶段、开始/取消 AI 回合、AI 阶段撤销与重开
- 新游戏页难度选择；对局页思考提示与操作门控；撤销到玩家决策点
- 自动化测试与固定种子基准

## 2. 算法与实现

### 2.1 搜索

`src/ai/ai_search.c`：

- **Negamax**：所有分数从行棋方视角计算；子节点分数取负。
- **Alpha-Beta**：根节点首个着法使用全窗口，之后用 `(-INF, -alpha)`。
  置换表命中可收紧 `alpha/beta`；节点结果的上/下界标签以收紧后的实际搜索
  窗口为准，避免把 fail-low 误存为 EXACT。
- **Pass**：节点没有合法着法时，如果对手也无着法，返回
  `ai_terminal_score()`；否则复制状态、切换行棋方、以同一深度递归并取负。
  搜索不依赖 `game_apply_move()` 的自动跳过，避免 pass 被静默吞掉。
- **终局分**：`±100000 ± 棋子差`（从当前行棋方视角）；平局为 0。
- **迭代加深**：深度 1..max_depth；上一层最佳着法用于下一层排序。
- **时间预算**：`timespec_get(TIME_UTC)` 毫秒；每 1024 个节点检查一次，
  根节点每个着法前检查。未完成的深度不会覆盖上一层完整结果。
- **置换表（Hard）**：Zobrist（棋盘 + 行棋方），`1<<16` 项直接映射，
  保存 depth/score/EXACT/LOWER/UPPER/best move。
- **着法排序**：先按静态位置分排序，再把置换表/上一层最佳着法提升到首位；
  角点 +1000，静态位置分 ×4。
- **残局**：Hard 在空格 ≤12 时把深度扩展到剩余空格数；时间不足则保留最后
  完整深度。

### 2.2 评估

`src/ai/ai_eval.c`，所有分量均为 `own - opponent`：

| 分量 | 定义 |
|---|---|
| corners | 己方角点数 − 对方角点数 |
| mobility | 当前合法着法数之差 |
| potential_mobility | 与对方棋子相邻的空格数之差（潜在机动性） |
| positional | 位置表分值之和；角点单独计分，位置表角点为 0 |
| stability | 通过己方角点沿边连续相连的边子数之差（保守估计） |
| frontier | 对方前沿子 − 己方前沿子（前沿子越少越好） |
| discs | 棋子数之差 |
| parity | 空格为奇数 +1，否则 −1 |

权重（开局 / 中局 / 残局）：

```text
corners   100 / 120 / 140
mobility   30 /  25 /   8
potential  12 /  12 /   5
positional  8 /  10 /   8
stability   8 /  14 /  18
frontier   10 /  10 /   6
discs       0 /   2 /  12
parity      0 /   2 /   0
```

阶段按空格数划分：≥44 开局，≥16 中局，其余残局。开局刻意不给棋子数权重，
避免早期贪吃；残局提高边稳定子与棋子数权重。

难度化评估：Easy/Medium 的总分只使用基础分量（corners、mobility、
potential_mobility、positional、discs）；Hard 额外计入 stability、frontier
与 parity。所有分量字段始终计算并保存在 `AiEvaluation`，便于解释与测试。
边缘位置分（即时形状、X/C 风险）与稳定子（持久归属）语义不同，属于有意
组合而非重复计数；角点不进入位置表，前沿子不计角点。

### 2.3 难度

| 难度 | 算法 | 深度 | 时间预算 | 评估 | 随机性 |
|---|---|---|---|---|---|
| Easy | 单层静态评估 | 1 | 30 ms | 基础分量 | ±40 分，只影响着法选择 |
| Medium | Alpha-Beta + 基础评估 | 4 | 200 ms | 基础分量 | 无 |
| Hard | 迭代加深 + Alpha-Beta + 置换表 + 完整评估 | 10（残局扩展） | 500 ms | 全部分量 | 无 |

三档最终都经过 `rules_is_legal_move()` 校验；非法结果直接拒绝，绝不交给
对局层。

## 3. 线程与集成

- `AiWorker` 复制 `GameState` 与 `AiConfig`，后台线程只读副本；不持有
  `Match`、`App`、视图或全局状态。
- 取消与完成使用 C11 原子变量；`ai_worker_join()` 等待线程并释放任务。
- `app` 在轮到电脑时调用 `match_begin_ai_turn()`，每帧轮询工作者；完成后
  仍通过 `match_apply_move()` 校验并应用。
- 撤销、重开、返回菜单、退出、开始新对局都会先取消并回收旧搜索。
- 线程创建失败时同步调用 `ai_choose_move()`；搜索失败时选择第一个合法着法。
- 人机模式撤销一次回退到玩家上一个决策点；`AI_THINKING` 中撤销先取消搜索。

### 4.2 基准参数

- 构建：Release（`-O3 -DNDEBUG`）
- 种子：`0x5EED1234`，每组 20 局，9 组共 180 局
- 对局配置（固定深度，保证可复现）：Easy 深度 1；Medium 深度 4、10 秒上限；
  Hard 深度 6、10 秒上限；均使用对应难度的评估分量
- 局面探针使用实际应用参数：Easy 深度 1 / 30 ms / 随机 40；Medium 深度 4 /
  200 ms；Hard 深度 10 / 500 ms，空格 ≤12 时残局扩展
- 对手：Random（固定种子）、Greedy（单层贪心）；AI 互相对局时统计包含双方
- 任何 `illegal` / `failures` / `unfinished` 都会使基准进程返回非零

固定深度避免墙钟预算带来的运行间差异；`--games 20` 的实际耗时远低于 10 秒
上限（最大平均值见 4.4），因此固定种子下结果可复现。实际应用的时间预算由
4.5 的探针单独记录。

复跑校验：同一 `--games 20` 命令运行两次，9 组的 W/D/L、nodes、cutoffs、
tt_hits、ai_moves 与 max_depth 完全一致；只有墙钟 `avg_ms` 随机器负载变化
（例如 Hard vs Random 31.4 ms → 95.4 ms）。这说明对局结果由固定深度与种子
决定，而不是由运行速度决定。

复现：

```bash
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release -j
./build-release/bin/reversi_ai_bench --games 20
```

## 5. 界面人工验证

显示恢复后，在 1100×832（HiDPI）窗口中用真实鼠标事件验证了交互流程。
以下描述的是流程，具体 AI 着法会随难度与最终参数变化：

- **新游戏页**：Computer 模式可选；Black/White 颜色按钮与 Easy/Medium/Hard
  难度按钮均能切换并高亮；先手颜色与难度在 Local 模式下正确禁用。
- **人机执白（Hard）**：开始后电脑自动占先；状态栏显示
  “Computer is thinking”，侧栏回合卡显示 “Computer thinking”；思考期间
  暂停按钮禁用，撤销/重开/返回菜单可用，棋盘不接受落子。
- **AI 自动落子**：玩家落子后电脑自动回应；分数、最后一步与回合文本同步更新。
- **撤销到玩家决策点**：点击一次 Undo 同时撤回玩家与电脑的应手，回到玩家
  落子前的局面；此时 Redo 可用、Undo 禁用。
- **思考中撤销**：玩家落子后、电脑思考期间点击 Undo，搜索被取消，局面回到
  玩家落子前，电脑没有在之后补落子。
- **重做**：Redo 恢复玩家落子并重新启动 AI，电脑随后自动落子。
- **重开**：Restart 确认后棋盘重置，执白时电脑重新开局落子；Cancel
  关闭确认框且棋盘保持不变。
- **人机执黑（Easy）**：开始后显示 “Black to move”，电脑不会抢先落子；
  玩家落子后电脑自动回应，撤销按钮在玩家有决策点后启用。
- **暂停/继续**：思考之外可正常暂停并继续，暂停层与侧栏状态一致。
- **窗口冒烟**：`app.smoke` 与 `reversi --frames` 在当前显示会话中通过。
